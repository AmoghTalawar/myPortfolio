    Watch a task find where to run

    A phone sends an image over the private 5G network. The scheduler then decides whether it runs at the edge, in the cloud, or back on the phone.

    Paper presented at ICAN 2026 (Springer Nature)

    Phones on a private 5G standalone network send image-classification requests. For each one, the system decides whether an edge pod or the cloud backup should run it, then stores the results for retraining.

    View code
    1. Phone Programmable SIM, UE pool 10.45.0.0/16
    2. Radio USRP B210 and srsRAN gNB, band n78, 20 MHz, 30 kHz SCS
    3. 5G core Open5GS on a VM, UPF GTP-U tunnel, live throughput monitor
    4. Edge MicroK8s running 9 CIFAR-10 inference pods
    5. Cloud OpenStack DevStack with a Docker backup node and a storage VM

    Three ways to choose where a task runs

    • MILP gateway: Pyomo with HiGHS or CBC, minimising latency within deadline and resource limits, using live bandwidth and edge load
    • DQN scheduler: PyTorch network trained on past scheduling data that picks the pod with the best predicted reward, extended with GNN-based node scoring
    • Heuristic fallback: CPU, memory and queue thresholds for when the model is unavailable

    ~56%lower latency than a cloud-only baseline, measured on the testbed

    Explore the brain behind the data

    Six brain regions and networks often studied in ADHD research. Select one to see what it does.

    WiDS Datathon 2025: 32nd public, 147th private, among 1,075+ global teams

    A team project on the Healthy Brain Network dataset. The model predicts a person's sex and ADHD diagnosis from sociodemographic, emotion and parenting questionnaires, combined with connectome data that maps how 200 brain regions connect.

    View dataset
    1. Data Connectome, demographic, emotion and parenting tables
    2. Clean Merged tables, KNN imputation, encoded categories
    3. Reduce PCA from 19,900 connectome features to 150 components
    4. Balance SMOTE for ADHD and sex class imbalance
    5. Model Stacking and bagging, tuned with GridSearchCV
    6. Evaluate Cross-validation, accuracy and weighted F1

    What the data showed

    • Strong behavioural signals: SDQ_Total and CBCL_Total were among the most predictive features, and combining them captured emotional-behavioural interactions
    • A surprise: I expected parenting data to be a top predictor, but brain connectivity patterns were far more influential
    • Girls with ADHD: the analysis pointed to distinct connectivity patterns, particularly in the default mode network

    Results

    A research project, not a diagnostic tool.

    Challenges and how I handled them

    • High dimensions: 19,900 features from 200 regions were reduced with PCA, then selected by statistical analysis
    • Class imbalance: SMOTE kept the model from favouring the larger groups in ADHD diagnosis and sex
    • Limited hardware: large matrices overwhelmed my laptop during PCA, so heavy runs moved to Google Colab
    • Reading the results: academic papers on connectomes and ADHD helped turn statistics into neuroscience

    Why it matters

    Girls with ADHD are often underdiagnosed. Understanding how ADHD appears differently across sexes could support earlier identification and fairer assessment.

    An 8-bit processor my team designed and simulated in Logisim. It uses a 2-address format with immediate addressing, so an instruction such as ADD R2, #03 names a register and carries its constant inside the instruction.

    View project site

    One instruction in five steps: ADD R2, #03

    1. T1: Address MAR ← (PC), and the control unit issues Read
    2. T2: Read MBR ← (memory), PC ← (PC) + 1
    3. T3: Load IR ← (MBR)
    4. T4: Execute ACC ← (R2) + #03
    5. T5: Write back R2 ← (ACC)

    What I built

    • ALU: 8-bit addition, subtraction, AND, OR, XOR and shifts
    • Register bank: 16 general-purpose registers, R0 to R15, selected by a 4-bit address
    • Control unit: decodes each instruction and signals the PC, memory, IR, ALU and registers in sequence
    • Status flags: a processor status word reporting parity, zero, sign and half carry

    What it taught me

    • Instruction encoding: balancing the opcode, operand fields and immediate value within limited bits
    • ALU inputs: feeding register and immediate operands into the ALU without making it much more complex
    • Timing: keeping each stage in sync as the control unit handles different instruction types
